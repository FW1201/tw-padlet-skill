# Wildcard 情境遊戲設計與驗收

本指引適用 Arcade Wildcard；實際生成、檔案與分享以當時介面和帳號為準。目標是讓學習者在有意義的情境中做事、看見後果並調整策略。避免僅將選擇題依序貼上背景；若使用者明確要求測驗，可尊重需求並說明可選的遊戲化方式。

## 1. 從使用者輸入形成設計

1. 擷取教材事實和來源、學段、目標、時間、設備及限制；素材不足或關鍵事實不確定時標記待確認，不自行編造來源。可給不影響正確性的合理預設並標明；未指定課時不要假裝已知。尊重所提供的素材使用權限，避免將學生個資帶入遊戲。
2. 先提出一個具體的玩家身分、任務及學習目標，例如「太空站物流員調整貨艙左右重量使其平衡」，讓學習目標直接影響玩家是否能完成任務。
3. 從下列機制依教材選 1 個主要操作和至多 1–2 個輔助操作，說明為何能展現該目標：拖放、移動、配給、排序、組合、建構、調整參數、觀察、比較證據、取捨、模擬或分支決策。操作不保證由生成器實現；桌機與觸控都需考慮，拖曳應有點選替代操作。不要為了種類數目犧牲可理解性。
4. 寫出核心循環：觀察狀態 → 採取操作 → 狀態可見變化 → 根據回饋修正 → 達成關卡目標。至少兩種有意義決策、持續可見的狀態或資源、與決策相連的回饋、錯誤後可恢復路徑；不要只有點選答案後顯示對錯。若目標本身僅適合判讀，將推理或證據選取設計成操作的一部分，仍以學科正確為先。
5. 設計 2–3 個逐步增加概念或條件的短關卡（可依課時及使用者需求調整），具體列每關初始狀態、玩家操作、規則、成功及失敗後果、提示和來源。避免時間壓力、扣分或生命值壓過學習；提供不計時或延時選項，如生成器能支援。
6. 安排最後完成畫面：任務成果、錯誤後修正過程或可觀察證據、對應概念；分數與排行榜僅在有教學意義、帳號與分享設定允許時採用，不將速度視為學習唯一證據；合法的不同解法或較多步驟不應自動扣分，以免抑制探索。

## 教材上傳與遊戲內容的對應

1. **盤點並讀取**：先列每個檔案或網址的標題、類型、可讀取狀態與範圍。教師有指定頁碼、章節、時間範圍時，以指定範圍為界；PDF 沒有文字層時可用影像辨識／逐頁閱讀，但應標記辨識不確定之處。受權限、登入或格式阻擋的來源標為無法讀取；禁止根據檔名猜內容。
2. **建立映射表**：每列記錄「來源 ID、頁碼／段落／時間戳、可確認的重點、課程目標、對應關卡、玩家操作、正誤或狀態回饋」。區分來源明示內容、教師提供條件及為遊戲設計新增的虛構情境；遊戲情境不可改寫來源事實。必要時標明不納入範圍、容易混淆概念與正確示例。
3. **按素材選玩法**：教材中的圖表／數據可成為玩家調整與觀察的狀態，程序可成為排序與操作步驟，論證資料可成為挑選證據與比較後果；不得將抽象主題硬套互不相關的機制。挑選代表性片段，對應學習目標與課時；不可假設所有上傳內容都已涵蓋。
4. **區分三種事實**：「Agent 讀到素材」「介面顯示已附加」「Padlet 生成內容顯示使用了素材」各自記錄，前者不等於後兩者。附件由平台上傳時檢查檔名及狀態；網址確認可公開讀取的程度，需登入或失敗即標示未確認。遊戲生成後比較實際關卡與映射表；無法檢查則標示未驗證，勿宣稱已導入全部教材。
5. 使用 `node scripts/tw-edtech-padlet.mjs wildcard-check --input <對應表.json>` 可檢查資料結構與來源片段 ID；參見 `assets/wildcard-alignment.example.json`。這只驗證引用與必填欄位，不會讀檔、上傳、理解教材或證明事實正確。`extractionStatus` 和 `attachmentStatus` 分開填，partial／unknown 有警告，須由教師或 Agent 依實況檢查。不要把密鑰、學生個資或不必要的教材全文寫入紀錄。

範例映射：`教師教材第 2 頁例題 x + 3 = 7 → 目標：等式兩側做相同運算 → 貨艙關卡：兩側各減 3 → 狀態 x = 4 → 代回 4 + 3 = 7`。若教材只有第一題，第二題與第三題屬自編延伸，須標示並核對年級、來源與教師要求，不得稱為教材原題。

## 2. 構成送入 Wildcard 的提示詞

依素材和課堂條件具體填寫以下模板；不要原封不動提交占位符。使用者希望直接建立時，以已授權的非敏感材料和已登入介面繼續，不必為一般設計決策反覆詢問。

```text
請製作繁體中文的互動學習遊戲「[名稱]」。對象：[年級與先備知識]；預計遊玩 [時間]；設備：[裝置與操作需求]。
教材與界線：[來源標題、實際已讀頁段、教師要求及可用檔案／連結；標出不得超出的內容]。
素材對應：[來源片段／頁碼 → 目標 → 關卡 → 玩家操作 → 學科正確的回饋；未獲確認的素材或推論明確標示，不虛構]。
學習目標：[可觀察的 1–2 個目標]。
情境與任務：[玩家身分、可理解的故事及具體目的]。
玩家操作：[主要操作、點擊／觸控替代方式]。每回合讓玩家先觀察 [狀態]，再 [行動]；行動立即改變 [可見狀態]，玩家根據 [解釋性回饋] 調整，再 [下一步]。至少提供 [兩種具意義的選擇]；不要僅以選擇題或輸入答案推進。
規則與學科正確性：[狀態如何變化、允許與不允許的動作、勝負條件；禁止會造成錯誤概念的捷徑]。
關卡：[逐關列初始狀態、任務、可操作物、成功條件與難度遞進]。
回饋及復原：[針對錯誤解釋原因、保留或可重置狀態、提示與重試，不暴露無關答案]。
介面：[大而清楚的按鈕、色彩和文字雙重提示、鍵盤／觸控或替代方案、清楚指引及重玩]。
結算：[顯示達成目標和推理證據；若適合才採計分，說明計分，合法的多步解法不因步數扣分]。
請優先完成核心互動、每關成功與失敗路徑；不要虛構多人同步、平台資料回傳或未驗證功能。素材無法讀取時請清楚提示，不要捏造內容。
```

### 實例：七年級方程式「太空貨運平衡站」

玩家是物流員，左右艙重量必須相等。操作不是直接填答案：點選兩側共同減去相同貨箱、或兩側同時平均分組，螢幕同步顯示天平和等式改變。第一關 `x + 3 = 7`，雙邊各減 3 得 `x = 4`；第二關 `2x = 6`，只允許雙邊各除以 2，得到 `x = 3`，不可先把 x 當已知重量；第三關 `x − 2 = 5`，雙邊各加 2 得 `x = 7`。每次操作呈現等式與對應貨艙；不合法操作解釋為何破壞等量關係並可重試；完成時代入原式驗證。按鈕與點選是主要可用操作，拖曳僅在實際可用且有替代方式時採用。此為設計範例，不代表所有生成版本具備這些能力。

其他可選情境：自然課依證據調整溫室條件並觀察變化；語文課移動事件卡並根據文本線索修正故事順序；公民課依限制分配社區資源並比較後果。先核對模型與素材是否足以支持回饋，別將假設呈現為真實世界事實。

## 3. 建立、版本修改與驗證

- 確認目前介面支援的材料輸入，使用文件或網址時確認實際成功加入；受保護網址不能假設可讀。記錄資料來源、來源是否實際呈現及看不到的部分。不上傳未經授權的敏感檔案。
- Wildcard 可用自然語言描述或範本；完成生成前顯示進行中，等待可能超過五分鐘。超時先回 My games 或現有任務查狀態，避免重複建立。附件、生成與每次修改可能受當時額度限制。
- 生成完成後先確認遊戲存在、素材的附加狀態及可見內容和來源對應；使用者只要求生成與教材契合時，無須持續試玩或逐關測試平台機制。若使用者要求遊戲驗收，再依指定範圍檢查操作、回饋與重試；不得用生成成功推論未測功能已通過。手機、鍵盤、多人與無障礙只有實測成功才能標記通過。
- 逐項記錄：情境與目標、可執行操作、可見狀態變化、選擇後果與回饋、錯誤復原、完成條件、教材來源和關卡正確性、裝置／可讀性、讀回／分享設定。每項標記通過、失敗或未測及實際觀察；單純選擇題仍存在時標為未達設計要求並提出具體修正。
- 每次只針對一個可重現問題修改，描述「關卡／起始狀態 → 操作 → 實際結果 → 預期結果」，保留版本編號，生成後按使用者指定的驗證範圍讀回修改；未經試玩的部分標示未測。修改分數或難度可能影響舊版排行榜，依介面讀回；不要宣稱已保留。
- 可用時評估 Arcade 排行榜、即時活動、遊戲鎖定、次數限制與分享連結／QR；依課堂目標與隱私選擇，不預設啟用。官方文件目前指出 Wildcard 無 Insights；不承諾自動取得詳細學習歷程。
- 最終報告遊戲 URL、來源是否讀入、版本、測試日期／帳號方案（可確認時）、已測與未測、實際分享狀態。未經跨帳號測試不得宣稱所有學生皆能開啟。

官方基線：[Wildcard games in Arcade](https://padlet.help/l/en/article/5wzjc3tuk2)（2026-11-26 查閱）。官方將 Wildcard 標示 beta；可用性、額度及介面可能變動。
